# evals/ —— 基准评测（改 skill 后跑回归）

> 用途：证明「这个 skill 真的让输出变好了」。每次改动 workflow.md / rubrics/ / models/ 后跑一轮，与基线对比，防退化。

## 方法

1. **任务**：从 [briefs/](briefs/) 取任务简报，同一简报跑两遍——**带 skill**（按 workflow 五步工序）与**不带 skill**（直接让模型写）。
2. **盲评**：两份产出去掉标识、打乱顺序，交审阅方（人或独立 agent）按 [scoring.md](scoring.md) 打分。
3. **硬指标先行**：评分表中可直接数、可直接查的项（字数档位、数据出处、块结构、筛项通过数）机器可判，占 60%；软评（口吻、立意）占 40%。
4. **记录**：每轮结果追加到 [runs.log.md](runs.log.md)，含日期、commit、总分、逐维分、失败项。

## 判定

- **有效**：带 skill 总分 ≥ 基线 + 10%，且硬指标无一项退化。
- **回归**：已通过的简报在新版本下掉档 → 改动引入退化，先修再发。

## 目录

```
evals/
├── README.md      # 本文件
├── scoring.md     # 评分表（维度+分值+判分规则）
├── briefs/        # 任务简报（输入，不随版本改）
└── runs.log.md    # 每轮跑分记录
```

## 约束

- 简报里的素材（数据/事例）视为"用户提供的材料"——按工序红线，产出必须溯源到这些材料，不得外加编造。
- 评测不联网补料，保证两遍（带/不带 skill）输入一致。
- 软评存在 AI 评审偏置：双人盲评时交换顺序各评一遍，分差 >15% 的维度标记人工复核。
