# 范文拆解卡：汇报稿与发言稿（briefing-speech）

> 素材来源：《怎样写作》第十讲原书实例。本卡是拆解，不是原文；起草前通读本卡 + ch10。
> 一句话心法：**汇报稿具有先决性——建议部分相当于决策的初始文本**；发言的要诀是真。

## 卡 1｜农业农村片区会汇报稿——三段同轴样板

| 维度 | 拆解 |
|------|------|
| 场景 | 片区会汇报，聚焦粮食生产、农民增收、"三农"政策 |
| 骨架 | ①面临的突出问题（定性先行："大部分不是区域性的，而是普遍性的；是苗头性的，但不是决定性的……可以克服和解决"——问题真切不夸大）→ ②措施及成效（五项措施全部对着前面四个问题：抗旱保夏粮/差价补贴/农技推广项目/信贷支农/示范区）→ ③几点建议（五条全部站在农业农村工作全局，没有一条为本省要钱要项目） |
| 文风 | 说明文写法，干净利索；每条建议都有本省先行实践的成效托底 |
| 结构诀 | **问题—措施—建议三段同轴**：措施回答问题、建议超越本位——汇报的落脚点是让建议被采纳 |
| 可复用 | 一切"向会议要决策"的汇报：定性给判断（不夸大不缩小）、措施对问题（一条对一条）、建议站全局（不为本单位要钱要项目） |

## 卡 2｜中心组学习现场发言稿——"三个结合得紧密"样板

| 维度 | 拆解 |
|------|------|
| 场景 | 中心组学习，边听马克思主义哲学辅导边写，不事润色保留原汁原味 |
| 骨架 | 从授课内容入题（"艾思奇是各位同乡"拉近距离）→ 三点体会（9+8+5 条）→ 落到"学与干、说与做、部署和落实、守规矩和敢担当"四个关系 |
| 文风 | 真诚呼应授课（"听了两个多小时，胜读十几本书"）；敢于查摆（"过河的船有了、掌舵的有了，操桨用力划的人不多——实度不够"）；比喻拉近距离 |
| 结构诀 | 每条体会都与思想实际和工作实际挂钩——发言不能与会议内容两张皮 |
| 可复用 | 学习/培训发言骨架：呼应授课（引观点）→ 自己的思考（每条联实际）→ 查摆与落实 |

## 场景速查（先定哪种发言，再选骨架）

| 场景 | 骨架 | 要害 | 出处 |
|------|------|------|------|
| 工作汇报 | 三段同轴（问题→措施→建议） | 先决性：定性先行、措施对应、建议站全局 | ch10 |
| 即席汇报 | 会前备提纲：块标题+关键数据位 | "即席"不等于无准备；该提的建议没提可能造成决策失误 | ch10 |
| 学习会发言 | 呼应授课→体会→联实际 | 三个结合得紧密；真诚呼应不吹捧 | ch10 |
| 座谈会发言 | 基本情况及问题→做法及经验→规律 | 立足本部门职能、站在所代表的方面说话 | ch10 |
| 对照检查 | 情况→问题→原因→整改（递进，不是并列） | 问题是贯穿始终的主线；前面查摆的，后面必须整改 | ch10 |

## 合成示范（原书无此稿，按原书标准写就，供模仿口径用）

> 场景：某县水务局在县政府常务会上汇报农村供水管网改造方案（约 900 字，会前印发）。
> **【示范稿】**——注意定性先行、措施对问题、建议站全局三段同轴：

```
关于全县农村供水管网改造的汇报

  一、面临的突出问题
  全县农村供水管网 60% 建于 2008 年前，当前问题有三个：
一是漏损重，管网漏损率 28%，年漏水约 180 万吨；二是水压低，
12 个村高峰期末端水压不达标，去年冬天 X 村曾连续停水 5 天；
三是维修慢，乡镇无专业队伍，平均修复时长 26 小时。
总体看，问题是设施老化带来的阶段性问题，不是管理问题，
通过系统改造可以解决。

  二、拟采取的措施
  针对漏损：分两年改造主管网 86 公里，同步加装分区计量
设备 42 套，改造后漏损率控制在 12% 以内。
  针对水压：X 村等 12 个村增设加压泵站 3 座，纳入一期。
  针对维修慢：组建县供水公司乡镇维修站 4 个，承诺修复
不超过 8 小时，24 小时值班电话向社会公布。

  三、两点建议
  一是资金整合建议：农村供水、高标准农田、移民后扶三块
资金各有投向但管网改造都能沾边，建议县里统筹整合、一次
施工，避免今天挖明天填。
  二是价格机制建议：改造后运行成本上升，建议按程序启动
水价成本监审，同步对脱贫户设补贴档，不让一户因改造用不起水。

  以上汇报，请审议。
```

**示范稿拆解**（自己对照）：问题段定性先行（"阶段性问题，不是管理问题"——给会议一个可决策的判断）；措施段每条开头就是"针对XX"（一条对一条）；建议段两条都超越本部门立场（资金整合是全县视角、价格机制带兜底），且有成效托底意识。字数 900 干净利索——常务会半天审十几个议题，汇报稿必须观点立得住。

## 使用规则

1. 起草前：本卡 + ch10 + rubrics/speech.md（汇报/发言节）。
2. 汇报稿的"建议"必须有用户材料的成效/经验支撑——拍脑袋建议是反面模式。
3. 对照检查类：AI 只协助整理结构与语言，查摆问题的事实必须由本人提供（真实诚信是试金石，AI 不能替人认错）。
